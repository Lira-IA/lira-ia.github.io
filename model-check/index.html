Is your code still calling a model that's about to die?

Claude Sonnet 4.5 shuts down on November 30. Gemini 2.5 Pro and Flash get silently rerouted on December 1. GPT-5 and o3 die on December 11. Paste your code or a public GitHub repo and find every dead or dying model ID, with file and line, in a few seconds. It runs in your browser. Nothing is uploaded.

Public repos only. Reads up to 400 source and config files through GitHub's public API.
Code, .env, YAML, logs, a whole diff. Anything with model names in it.
Pick your project folder. Files are read locally and never leave this tab. node_modules and build folders are skipped.

Run it in CI

Same data, same rules, as a single Python file with no dependencies. It exits with code 1 when a model ID is already dead, so the build breaks before production does.

curl -sL https://lira-ia.github.io/model-check/check.py | python3 - . --fail-on dead

GitHub Actions, with an annotation on the exact line of every hit:

- uses: actions/checkout@v4
- uses: Lira-IA/lira-ia.github.io/action@main
  with:
    fail-on: dead   # or: soon (90 days), never

Options: --fail-on soon --days 30 to break 30 days before a shutdown, --json for machine output. Read the source (MIT, about 120 lines, its only network call downloads models.json).
